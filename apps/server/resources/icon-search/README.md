# 图标搜索维护数据

此目录保存经过确认的中文译文，不保存全量图标清单或 SVG。全量定义、隐藏定义和别名始终在构建时从当前锁定的 `@iconify/json` 读取。

维护范围覆盖当前锁定的 `@iconify/json` 中全部已注册图标集，收录可依据元信息确认的名称、名称词及分类译文。图标包和搜索数据版本以 `manifest.json` 为准。

有中文检索词不表示名称中的每个词都已翻译。未译内容包括品牌及专有名称、数字或技术代号，以及无法仅凭元信息确认含义的词，继续保留原文检索。

复核保留英文的内容时，同时检查无中文的条目、已部分翻译的名称，以及译文中仍出现英文的部分。未命中现有词表不能直接作为保留依据；须结合具体图标核对品牌名、普通组成词和复合词，并保留数字、型号及样式的含义。其他图标的局部译文不能代替当前图标的完整名称译文。

名称词和 categories 中明确列出的分类关系在构建时从当前图标包自动提取，所有图标集采用同一规则，不维护重复的英文词项或成员名单。分类译文按图标集与分类归属保存，应用于当前包明确列出的全部成员；别名只有被明确列为分类成员时才获得分类词。分类原文和译文保留辅助字段权重。

维护文件是按归属和英文源文稳定排序的 JSONL。图标译文的 `owner` 是完整图标 ID；分类译文的 `owner` 明确保存 `prefix` 和分类名。`source` 必须是对应图标的完整名称或名称词，或者对应分类的完整原文或词项。翻译仅表达该源文已有含义。别名按自身名称维护译文，不自动继承父图标的译文。

同一个源词按其归属分别校对，例如 `cell-tower` 中的 `cell` 表达“蜂窝网络”，`cell-merge` 中的 `cell` 表达“单元格”，不全局共享译法。复合词需要整体表达时，使用完整名称作为来源，例如购物车或信用卡；不把复合词的含义分配给单个不等义的名称词。`bell` 的“铃铛”译文不会补充“通知”“提醒”等用途词。

`manifest.json` 记录格式版本、维护时的图标包版本、数据版本、文件路径和 SHA-256。修改 JSONL 后更新可读的数据版本和对应校验和；构建还会自动计算派生文档内容指纹，避免遗漏手动版本更新时复用旧索引。随后运行：

```bash
pnpm --filter @rev30/server icon-search:validate
pnpm --filter @rev30/server icon-search:build
pnpm --filter @rev30/server icon-search:verify
```

校验和格式损坏、重复记录或声明文件缺失会使构建失败。图标包升级时，维护版本可以暂时滞后；缺少维护记录不阻断构建。已不存在的归属、源文或分类关系会列入构建输出的 `excluded` 并暂不进入产物，修正维护文件后再恢复。生成的压缩 JSONL 位于 `apps/server/generated/icon-search`，不纳入 Git；发布构建会将其复制到 `dist/icon-search`。

维护数据与相关实现验证完成后，再按需更新功能和维护说明。一次性校对清单、覆盖数量与比例、未译明细及性能报告保存在项目外的临时目录，不纳入 Git。
