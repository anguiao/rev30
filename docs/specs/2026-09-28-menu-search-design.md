# 菜单搜索与快捷导航设计

## 背景与范围

后台已有按当前用户权限生成的侧栏菜单。菜单层级较深或侧栏收起时，用户需要逐层寻找入口。本次增加独立搜索弹窗，帮助用户按名称快速打开可见菜单。

首版仅搜索当前用户可见且已配置跳转地址的内部菜单和外链，分别沿用现有菜单的 `path` 和 `externalUrl`。纯目录、仅用于展开子菜单的分组不作为结果；若父项本身具有跳转目标，仍可纳入，不以是否为叶节点判断。

不额外加入侧栏底部的“个人设置”和“通知公告”固定入口，不加入隐藏菜单、收藏、最近访问、搜索历史或其他操作命令。不做拼音、模糊匹配或业务数据搜索。

## 方案选择

采用独立搜索弹窗，由侧栏入口或 Ctrl/Cmd + K 打开。结果平铺展示，适合键盘选择，也适用于侧栏收起状态。

另一方案是在侧栏原地过滤菜单树，但深层结果仍受树结构影响，收起状态也需要额外展开，因此不采用。

## 入口与界面

搜索入口放在侧栏品牌区下方、菜单上方。侧栏展开时显示搜索图标、“搜索菜单”和平台对应的快捷键提示；收起时保留搜索图标，并提供可访问名称及提示。

弹窗覆盖后台界面，在视口上部水平居中，包含输入框、可滚动结果列表和简短键盘提示。每条结果显示已有菜单图标、名称和上级菜单层级；没有上级时省略层级行，没有图标时不补造图标。新窗口打开的项提供相应提示。同名菜单保持为独立结果，通过层级区分。

结构示意如下，具体尺寸、间距和样式沿用现有主题与 Naive UI，在实现时调整：

## 搜索与状态

- 每次打开时清空查询并聚焦输入框。空查询列出全部可搜索项，按现有菜单树的深度优先顺序排列；数量较多时滚动浏览，不分页或截断结果。
- 输入变化后立即在本地过滤。查询去除两端空白，按菜单自身名称做不区分英文大小写的连续子串匹配；不分词、不匹配父目录、路径或权限编码，不增加相关性排序。
- 上级层级只用于展示。例如“登录日志”“操作日志”可以被“日志”命中，不能仅因归属“运维管理”而被“运维”命中。
- 打开、查询变化或菜单数据更新后，选中当前结果的第一项；无结果时不保留选中项。选中项在键盘移动时保持可见。
- 有可搜索项但没有匹配结果时显示“未找到匹配的菜单”；没有任何可搜索项时显示“暂无可访问菜单”，搜索入口仍可使用。
- 菜单随会话更新时，候选、结果和选中项同步更新，不保留已移除的旧结果。查询和选择状态不持久化。

## 键盘与导航

Ctrl/Cmd + K 在后台壳层内打开搜索；已打开时聚焦搜索框，不清空现有查询或重复打开。快捷键与入口提示按平台保持一致：macOS 使用 Cmd + K，其他平台使用 Ctrl + K。

焦点在普通输入框或文本域内时，仍可通过快捷键打开搜索；焦点在富文本编辑区（可编辑的 `contenteditable` 区域及其后代）时不触发。其他模态抽屉、对话框内不通过快捷键打开搜索，这条限制同样适用于其中的普通输入框。已被控件处理的事件、按键重复和输入法组合输入不触发全局快捷键。

输入框中的上下方向键循环选择结果，Enter 打开选中项；没有结果时 Enter 不执行导航。输入法组合输入期间不执行结果选择或打开操作。鼠标可直接点击结果，悬停可切换当前选中项。

Esc、关闭按钮或点击遮罩均关闭搜索。输入法组合输入期间的 Esc 留给输入法处理，不关闭搜索，沿用 Naive UI 现有的组合输入保护。弹窗限制焦点在自身内部，提供搜索输入、结果及选中状态的可访问语义；普通关闭后恢复打开前的焦点。焦点和 Esc 行为优先复用 Naive UI 的模态能力。

选择结果后关闭搜索，并沿用侧栏的打开规则：

| 目标 | 行为 |
| --- | --- |
| 内部菜单，当前窗口 | 通过 Vue Router 导航，保留已有的权限守卫和未保存内容的离开确认 |
| 外链，当前窗口 | 使用普通链接导航，保留浏览器离开页面时的既有保护 |
| 内部菜单或外链，新窗口 | 沿用 `openTarget`，使用 `_blank` 和 `noopener noreferrer` |

结果保留链接语义，鼠标修饰键和浏览器的新标签页打开方式与侧栏一致；Enter 的默认行为使用菜单配置的打开方式。新窗口打开保持用户操作的直接触发，不延迟到动画结束。

当前窗口内部导航前先释放搜索弹窗的焦点，避免干扰后续离开确认。若用户取消导航或保存中被原有守卫阻止，停留原页面，搜索保持关闭；不自动关闭业务抽屉或放弃编辑。已有 403、404 和会话失效处理继续生效。

## 数据与职责

搜索直接使用 auth store 的 `visibleMenus`。服务端已有授权与资源状态过滤，前端可见菜单又排除了隐藏节点及其子树；搜索不读取完整资源管理列表，不从全部路由补充候选，也不重复建立权限规则。

实现集中在前端后台导航区域：

- 后台壳层挂载搜索组件，连接侧栏入口与快捷键生命周期。
- 搜索组件负责弹窗、输入、结果列表和选择状态，使用现有契约中的菜单类型。
- 菜单遍历与名称匹配保持为可独立验证的纯逻辑，保留资源身份、导航信息及上级名称。
- 侧栏与搜索复用菜单链接规则；必要时提取小型共享组件或函数，不扩展为通用命令系统。

数据流为 `visibleMenus → 可跳转项与层级 → 名称过滤 → 结果列表 → 现有导航`。候选与结果采用响应式派生，不维护另一份持久化索引。本次无需新增接口、数据库字段、共享契约或搜索依赖；本地过滤也不增加网络加载、重试或错误提示流程。

## 验证与验收

只补充与新增行为和回归风险相关的测试，复用现有权限、路由及表单离开保护的测试基础：

1. 仅纳入可见、可跳转项；纯目录和隐藏子树不进入结果，可跳转父项不会因有子节点而被遗漏。
2. 验证名称包含匹配、大小写与两端空白处理、父目录不参与匹配、同名项层级展示及稳定顺序。
3. 验证空查询、无匹配、无菜单、会话菜单更新，以及每次重新打开清空查询。
4. 侧栏展开或收起均可打开搜索；验证平台快捷键及提示一致、普通输入框和文本域内可用、富文本编辑区和其他模态窗口内禁用，以及已处理事件、按键重复和输入法组合输入不触发。
5. 验证上下选择、Enter、Esc 和焦点恢复，以及已打开后再次按搜索快捷键只聚焦且保留查询。组合输入期间的方向键、Enter 和 Esc 不执行菜单选择、导航或关闭。
6. 验证内部路由、外链和新窗口规则；当前窗口导航仍经过原有守卫，取消离开时保留编辑内容。

实现阶段运行相关前端测试和类型检查，并按仓库要求完成 `pnpm check`。浏览器检查重点覆盖键盘与焦点行为、侧栏两种状态，以及明暗主题和窄屏下的可用性。
