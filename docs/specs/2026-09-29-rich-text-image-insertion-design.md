# 富文本图片选择与批量插入设计

## 背景与范围

当前富文本图片插入流程通过“选择图片 → 上传图片 → 确认”处理单张图片。选择与上传分开保留了上传前的确认机会，用户选错文件时可以取消而不产生服务器文件；但空预览框、文件选择按钮和上传按钮同时出现，操作关系不够自然。

本次完善富文本图片选择与批量插入能力，支持本地多图选择、逐张设置属性和一次性插入，并在公告编辑中接入图片库，复用此前上传的公告图片。通过重做 `ImageDialog.vue` 将两种图片来源纳入统一的选择与设置流程，最终确认同时完成上传和插入，保留“确认前不上传”的行为。

首版范围：

- 新增图片时，支持本地多图、图片库多选以及两种来源混合，统一加入待插入列表，一次最多选择 20 张。
- 每张图片独立设置说明、宽度和高度，支持移除、调整顺序，确认后按顺序一次插入。
- 公告图片库按用途隔离，允许公告编辑者共享使用，不限定上传人。
- 图片库跟随公告新增或编辑权限，不增加独立权限，不要求附件资源查询权限。
- 编辑正文中已有图片时，继续只编辑或替换当前一张。

头像继续使用现有上传入口，本次不增加头像图片库，也不专门改造头像归属校验。附件管理页仍负责附件管理，有删除权限的用户仍可删除正在使用的附件，删除不改写业务记录。

本次不加入跨用途选择、外部图片 URL、裁剪、批量统一设置属性、文件去重、上传秒传、断点续传、图库目录或标签管理。不涉及公告冲突检测、列表查询状态恢复和导入导出，也不增加针对图片弹窗期间正文外部更新的检测、提交阻断或自动取消逻辑。

## 已有实现与复用边界

- [ImageDialog.vue](../../packages/rich-text/src/features/image/client/vue/ImageDialog.vue) 已有本地预览、说明、比例联动尺寸、上传及取消行为；重做界面和候选状态管理，保留这些基础能力。
- [image Vue 入口](../../packages/rich-text/src/features/image/client/vue/index.ts) 负责打开弹窗、保存编辑器选区和确认插入；[image editor 实现](../../packages/rich-text/src/features/image/client/editor.ts) 负责图片动作与粘贴入口。
- [公告表单](../../apps/client/src/features/announcements/AnnouncementFormDrawer.vue) 已通过业务上传函数完成压缩、附件上传和稳定 URL 转换。
- [公告 repository](../../apps/server/src/modules/content/announcements/repository.ts) 已在保存正文时校验图片用途、读取策略、清理策略和图片类型，并更新附件引用。
- [附件清理](../../apps/server/src/modules/attachments/cleanup.ts) 已支持未引用附件清理；[附件列表](../../apps/server/src/modules/attachments/repository.ts) 已有分页、排序及使用位置查询能力。

图库复用现有附件记录和存储，不建立新的素材实体，不需要数据库迁移。`usage` 继续是非空字符串；公告业务决定本场景可以选择什么，不新增全局用途枚举或权限注册表。

## 方案选择

采用“统一待插入列表 + 逐张属性设置 + 最终上传并插入”：本地选图和公告图片库接入同一个列表，属性设置和最终确认共用，图片库在同一选择界面内浏览。

相比另开一个图片库弹窗，该方案不增加模态窗口层级，适合本地图片与图库图片混合处理。相比保留独立的“上传”再“插入”，最终确认承担上传确认，减少一个操作，同时避免选择文件后立即上传。选好文件即自动上传的方案不采用，因为用户应能在上传前检查和移除选错的图片。

## 界面结构

以下示意表示信息组织和操作关系，不固定像素尺寸。实际控件使用 Naive UI 和现有富文本主题；交互草图用于辅助理解，行为以本文流程、状态表和验收要求为准。

正式界面直接描述用户操作和图片状态，使用“选择图片”“已选图片”“上传”“插入”等文案，不出现“每批”“本批”“队列”“会话”等实现术语。本文中的批量、候选和会话等表述仅用于说明设计与实现约束。

空态只保留一个本地选图区域和图片库入口，不显示空预览、禁用的属性表单或独立上传按钮。未配置图片库的使用方不显示图片库入口。

- 列表项显示序号、缩略图、文件名和状态；当前项有明确选中态。
- 点击列表项只切换当前图片，保留其他图片的属性。右侧只展示当前图片的预览与属性。

- “移除”只移出本次待插入列表，不删除附件。移除当前图片后优先选中原位置的下一张，没有下一张时选中前一张。
- 查看图片属性时，若列表中仅有一张图片，则省略左侧列表和排序操作，保留预览、属性、移除及继续添加入口。列表清空后回到空态。
- 窄屏时列表与属性纵向排列；实际弹窗限制在视口内，内容区可滚动，最终操作区保持可访问。

## 选择与逐张设置

### 选择数量限制

插入模式中，本地图片与图库图片合计最多 20 张。该上限针对本次待插入列表，不限制正文中的图片总数；单张编辑模式仍只接受一张候选。空态提示“最多选择 20 张图片”，已有候选时显示“已选择 N / 20 张”。

文件选择、拖入、弹窗内粘贴及编辑器粘贴带入的初始候选，均在创建预览前检查剩余名额。非图片文件不计数并按既有规则提示；本地文件不去重，图库已选项按稳定 URL 去重。列表中读取中、读取失败、上传失败和上传成功的候选均占用名额，移除后释放。

一次新增的图片超过剩余名额时，整次拒绝新增，提示“最多选择 20 张图片，还可添加 N 张”；已经选满时提示“已选择 20 张图片，请先移除再添加”。保留已有列表、顺序、当前项及属性，不静默截取前几张。编辑器粘贴的初始候选超额时，打开空态弹窗并显示同样的提示；满额时仍允许浏览图库和取消已选项。

### 本地图片

1. 文件选择、弹窗内拖入和图片粘贴均可加入多张图片，按浏览器提供的文件顺序追加到列表。
2. 选择阶段仅在浏览器中创建预览、读取自然尺寸；不创建上传会话、不发起文件上传、不登记附件。
3. 一次新增多个文件后选中其中第一张，并进入属性区。取消系统文件选择框不改变当前列表。
4. 新图片说明默认取原始文件名，宽高默认取自然尺寸。用户可以清空说明；宽高使用正整数，始终按原始比例联动，并可恢复原尺寸。
5. 每张图片独立保存属性。上传适配器沿用现有压缩行为，压缩不覆盖本次确认的图片说明和展示尺寸，展示继续遵循富文本图片的防溢出样式。
6. 预览失败的图片显示错误，可重试读取或移除；不静默丢弃，也不带着无效图片继续插入。非图片文件不加入列表，并就地提示。

弹窗内的图片粘贴只作用于选图区域，不拦截说明等输入框中的粘贴。编辑器中粘贴图片文件打开该弹窗，并把文件作为初始候选；编辑器内部复制的富文本图片继续沿用现有粘贴规则，不重新上传。外部 HTML 图片过滤规则保持不变。

本次不按文件名、大小或内容哈希为本地文件去重。文件名相同不代表同一图片，用户通过列表检查和移除。

### 图片库

- 只展示当前用途的可用图片。公告入口固定为公告用途，不提供用途切换或“只看本人”筛选。
- 支持按文件名搜索，去除关键词首尾空白，做不区分英文大小写的连续子串匹配，不匹配 MIME、上传人或关联公告标题。
- 点击搜索按钮或在搜索框按 Enter 提交查询，并回到第一页；空关键词恢复全部可选图片。输入法组合输入期间不提交搜索。
- 服务端分页，每页 20 张，首版不提供页大小切换；按上传时间倒序，同一时间按附件 ID 倒序保持确定顺序。
- 跨页、搜索和来源切换保留已选项及其属性。图库中的同一图片在本批只添加一次，使用稳定内容 URL 识别重复项；也不重复添加本批已经上传成功、具有相同 URL 的图片。
- 当前正文里已经使用的图片仍可再次选择，后续不同批次也允许重复插入；各处图片说明和尺寸互不影响。
- 每个弹窗会话第一次打开图库时，从服务端重新读取第一页。当前弹窗内切换到属性区再返回图库，保留搜索与页码；关闭整个弹窗后不保留待插入列表、搜索或分页状态。
- 加载时显示加载状态；失败显示可重试错误；空库显示“暂无可用图片”，搜索无结果显示“未找到匹配的图片”。查询状态变化不清空待插入列表，过时的查询响应不能覆盖当前结果。

图库图片通过现有稳定内容 URL 预览。选入列表后读取自然尺寸，设置方式与本地图片一致；修改属性不改写共享附件元数据或其他公告内容。

## 最终确认与状态

最终操作的文案随本批内容变化：

- 有待上传的本地图片：`上传并插入 N 张`。
- 所有图片已有可用内容 URL：`插入 N 张`。
- 正在上传：显示上传状态并禁用重复提交，各列表项显示等待、上传中、成功或失败，不显示无法准确获取的百分比。
- 没有图片，或存在未完成的预览、无效属性、图片读取错误：禁用最终操作，并在对应项显示原因。

| 当前状态 | 用户操作或结果 | 下一步行为 |
| --- | --- | --- |
| 尚未选择 | 选择本地图片或图库图片 | 加入列表并读取预览；本地图片不上传 |
| 可调整 | 切换图片、修改属性、移除、排序 | 只改变当前弹窗状态 |
| 本地预览或图库内容读取失败 | 重试或移除 | 重试对应内容读取，不触发文件上传 |
| 可提交且存在本地待上传项 | 点击“上传并插入” | 固定本次列表、顺序和属性，开始上传 |
| 全部图片已有可用 URL | 点击“插入” | 按列表顺序一次插入 |
| 上传中 | 部分图片失败 | 处理完本批其余项并汇总错误，保留成功结果，整批不插入；恢复调整操作 |
| 上传部分失败 | 再次点击“上传并插入” | 只上传尚未成功的图片，已成功项不重复上传 |
| 上传后内容 URL 读取失败 | 重试 | 保留已上传 URL，只重试读取，不重新上传 |
| 用户已确认的本次提交中，所有图片上传及读取成功 | 无需再次确认 | 一次插入整批图片，关闭弹窗并恢复编辑器焦点 |
| 任意未完成状态 | 取消、关闭或编辑器销毁 | 不插入、不改原正文，丢弃本次候选状态；迟到结果不再影响界面或编辑器 |

“上传失败”与“文件已上传但预览读取失败”分开记录。前者允许重试上传，后者只重试读取。任一失败都会阻止本次提交插入正文；处理完本批其余本地项后，汇总错误并恢复调整状态。单独重试预览成功只恢复可提交状态，不自动插入，用户仍需点击最终按钮重新提交。用户也可以移除失败项后提交剩余图片，不自动决定只插入成功部分。

上传复用单文件上传函数，首版顺序处理本地项，避免同时发起不受控数量的上传。一个文件失败不丢弃其他项，继续处理本批其余本地项并汇总结果。上传期间禁用来源切换、属性编辑、排序和移除；取消仍可用。取消后停止启动后续上传，已经开始的请求可以完成，但不再触发插入。

在用户点击最终确认前取消，不产生服务器文件。确认后部分上传成功再取消、移除成功项或最终没有保存公告时，成功文件沿用现有未引用附件清理，不调用删除接口回滚，也不承诺文件上传的原子性。整批不部分插入指的是编辑器正文变更，而不是多次文件上传构成数据库事务。

选中后的预览、属性设置和图库浏览不预占附件、不写引用、不延长清理期限。图片可能在选择后被删除或清理，最终公告保存仍以现有服务端校验结果为准。

## 插入与单张编辑

### 批量插入

沿用现有图片动作入口保存弹窗打开时的编辑器选区。成功时在该位置按列表顺序插入连续的图片节点；原选区非空时沿用插入命令替换选区的语义，不因弹窗和按钮的焦点改变插入位置。

整批插入使用一次编辑器事务，形成独立的一个撤销步骤，不与前后输入合并；一次撤销移除整批插入并恢复被替换的选区内容，一次重做恢复顺序和每张图片的属性。预览和上传期间不插入临时图片节点。编辑器销毁或当前弹窗会话结束后，不执行迟到的插入动作。

图片节点仍只存 `src`、`alt`、`width`、`height`，不新增业务附件 ID、上传状态或本地文件信息。公告场景的 `src` 仍是 `/api/attachments/:id/content`，不保存临时签名 URL、浏览器对象 URL 或文件本地路径。

### 编辑或替换正文中的一张图片

选中图片后通过工具栏或图片快捷栏打开“编辑图片”，直接显示当前图片预览和属性，不显示批量列表、排序或追加操作。

- 可修改当前图片说明和尺寸，也可通过“替换图片”从本地或图片库选择一张替换图。
- 本地替换图在最终确认前不上传。替换时保留当前说明和展示宽度，根据新图片比例计算高度；原图片未设置宽度时使用新图自然尺寸。
- 本地替换的最终按钮为“上传并应用”，仅修改属性或使用图库图片时为“应用”。成功后更新原图片节点，不在旁边追加新节点。
- 编辑模式只接受一张候选。文件选择器和图库均为单选，选定图库图片后立即返回属性区，最终“应用”前不改正文；拖入或粘贴多张时提示“请选择一张图片”，保持当前候选，不静默取第一张。
- 取消或失败均保留正文中的原图和原属性。原图已无法读取时仍可选择替换图。

## 可访问性与交互细节

弹窗、文件选择、图片预览和表单优先复用 Naive UI 与现有 VueUse 能力。所有主要操作均可通过键盘完成，不要求拖拽或悬停；图库项具有多选语义，待插入项具有当前项语义，排序和移除按钮提供明确的可访问名称。

空态打开时聚焦本地选图入口；已有图片的编辑模式聚焦图片属性区。进入图片库后聚焦搜索框，返回属性区后把焦点放回对应图片的属性控件。关闭后恢复编辑器焦点。Esc 和关闭按钮按取消处理，输入法组合输入的 Esc 留给输入法；点击遮罩不关闭，避免误触丢失整批设置，不增加额外二次确认弹窗。

切换图片或移除当前项后焦点保持在可操作的对应区域。错误项有文字状态，预览错误与上传错误不能只用颜色区分。图片较多时列表与主内容可独立滚动，最终操作不因列表增长而移出可访问区域。

## 图片库查询与权限

公告模块新增只读入口 `GET /api/content/announcements/image-options`，不复用要求附件管理权限的附件资源列表路由，也不放宽该管理路由。

请求仅包含 `keyword`、`page`、`pageSize`。分页沿用共享分页约束，默认每页 20 条；选择器固定使用 20。调用方不能通过该接口传入用途、上传人或读取策略来扩大结果范围。

服务端固定筛选条件：

| 条件 | 规则 |
| --- | --- |
| 附件状态 | 已完成上传登记，且未软删除 |
| 用途 | `usage = announcement-content-image` |
| 读取方式 | `readPolicy = authenticated` |
| 清理策略 | `cleanupPolicy = unreferenced` |
| 类型 | 符合现有 `isRasterImage` 规则，排除 SVG 等不可用于公告正文的类型 |
| 上传人 | 不限制，允许同用途共享 |
| 引用情况 | 已引用与尚未引用均可选，不要求已保存到某篇公告 |

筛选在服务端分页前完成，`total` 也是符合这些条件的数量，不通过客户端过滤某一页来近似得到图片库。查询与公告保存使用一致的图片资格规则；必要时在公告模块内提取共用策略，避免两套规则漂移。

返回 `list`、`total`、`page`、`pageSize`。列表项复用 `attachmentSchema` 的元数据，不返回附件使用位置、关联公告标题或完整用户资料；应用层根据附件 ID 生成稳定内容 URL。

登录用户具备 `content:announcement:create` 或 `content:announcement:update` 任一权限即可访问，管理员沿用现有豁免。不要求 `content:attachment:list`，不新增权限资源或配置项。未登录和无上述权限分别沿用 401、403 响应。现有上传接口及内容读取策略不在本次重新设计。

## 组件、契约与数据流

### 富文本包

富文本包只处理图片选择和编辑，不知道公告、附件用途、业务权限和附件 API。

图片配置保留单文件 `upload(file) -> Promise<{ src }>`，并增加可选图片库查询能力：输入为 `keyword`、`page`、`pageSize`，返回分页结果，图片项只需要稳定 `src` 和展示用 `name`。未提供图片库能力时，保留完整的本地批量选图、属性设置和确认上传流程，不显示空图库入口。

职责划分如下，具体文件保持在 image feature 内：

| 单元 | 职责与依赖 |
| --- | --- |
| 图片选择界面 | 通过 `ImageDialog.vue` 承载模态布局、插入或编辑模式、来源切换及最终操作，组合以下单元 |
| 待插入列表与会话状态 | 管理候选、顺序、当前项、独立属性、文件与预览 URL、逐项上传结果；调用注入的上传函数 |
| 图片预览及属性表单 | 读取当前图片自然尺寸，编辑说明与比例联动尺寸，不访问业务 API |
| 图片库面板 | 搜索、分页、缩略图和多选状态，调用注入的图片库查询函数 |
| 图片动作及交互适配 | 接收初始图片文件列表、保存选区、一次插入或替换当前节点、处理关闭和编辑器销毁 |

不把所有队列、查询和上传调度逻辑继续累积到 `ImageDialog.vue`。按以上职责拆分必要的组件和状态逻辑，不引入通用上传平台或新的状态管理依赖。

图片配置类型和纯编辑器行为仍归富文本包，通过现有公开入口提供给使用方；不为了图片库导入 `@rev30/contracts` 的附件类型。`standard` 和 `all` 同步使用新的图片选择与插入流程；当前不含图片 feature 的 `compact` 保持原功能集合。

### 应用与服务端

公告客户端适配器把附件查询响应映射为通用图片库结果，并继续负责压缩、上传参数和稳定 URL 转换。共享请求与响应 schema 放在 `packages/contracts`，复用附件与分页约束；HTTP 调用和响应解析沿用现有 Hono client。

服务端公告模块负责图片库接口、授权和可选范围，复用附件表及现有业务图片校验。附件模块继续负责上传会话、存储、内容读取和清理，不加入富文本交互逻辑。

数据流为：

```text
本地文件 ── 本地预览 ──────────────┐
                                  ├─ 待插入列表 ─ 逐张属性 / 排序
公告图片库 ─ 稳定 URL / 图片名 ────┘
                                                │
                                          用户最终确认
                                                │
                                  仅上传仍待上传的本地项
                                                │
                                  全部图片有可用 URL 和属性
                                                │
                                   一次编辑器事务插入正文
                                                │
                                         用户保存公告
                                                │
                             服务端校验正文并更新附件引用
```

本地对象 URL 在候选移除、替换或会话结束时释放；可用性检查不重复创建无用上传。异步读取和上传结果归属于当前会话及对应候选，关闭弹窗后不得影响后来打开的会话。

## 保存引用与清理兼容性

插入图片只改变正在编辑的富文本文档，不立即保存公告，也不立即创建业务引用。保存草稿或发布公告时，服务端继续从规范化正文的稳定内容 URL 提取附件 ID，在公告写入事务中校验并刷新引用。

- 同一附件可被多篇公告共享引用；同一篇公告多处使用时引用记录按附件 ID 去重，但保留各图片节点自身的属性。
- 保存前图片已被删除、清理或不符合公告图片规则时，沿用现有正文图片错误，公告不部分保存；前端保留表单内容供用户移除或替换。
- 移出待插入列表、撤销编辑器插入，不直接删除附件或修改已经持久化的引用；引用变化以实际保存的正文为准。
- 未引用文件继续按现有保留期和定时任务清理；有引用时不会被未引用清理任务删除。图库浏览或临时选择不增加永久保留标记。
- 手工删除权限规则保持既有决策：有权限仍可删除正在使用的附件，不因图片库复用新增删除拦截。

## 验证与验收

只补充新增用户行为、业务边界及明确回归风险的验证，沿用现有图片、公告和附件测试基础。

### 交互验收

1. 空态不出现空属性表单或独立上传按钮；未配置图库的使用方仍可完成本地批量插入。
2. 文件选择、拖入和粘贴可以加入多图；本地与图库合计最多 20 张，包含读取或上传失败项。恰好达到上限可以加入，超额整次拒绝且不创建新增预览，原列表与属性保持；移除后释放名额，编辑器初始粘贴同样受限。最终确认前不调用上传函数，取消、移除选错图片和清空列表均不上传。
3. 逐张说明与尺寸在切换图片和浏览图库后保持；比例联动、恢复尺寸、前后移动、移除后的选择及单图布局符合本文规则。
4. 图片库查询和翻页正确，跨页选择保留，同一图库项不重复加入；本地与图库图片可混合，来源切换不丢失属性。
5. 混合来源只上传本地待上传项；任一上传或上传后读取失败时继续处理其余本地项，全部处理完后汇总错误并恢复调整，不部分插入，成功项不重复上传。上传成功后读取失败只重试读取；移除失败项后可提交剩余项。
6. 取消上传中的弹窗或销毁编辑器后，停止启动后续上传，迟到结果不插入、不影响新会话。
7. 插入位置、顺序及各图片属性正确；一次撤销和重做对应整批操作，撤销同时恢复被替换的选区内容，不与相邻文字输入合并。
8. 单张编辑保持替换语义；确认前不上传，多文件输入明确拒绝，取消或失败不改变原节点。说明输入框粘贴和既有内部图片复制行为不回归。

### 服务端与契约验收

1. 公告新增或编辑权限任一满足即可查询；没有附件资源权限不影响使用，只有附件管理权限不能替代公告写权限。
2. 用途、读取策略、清理策略、类型及删除状态在分页前过滤，结果与总数一致；他人上传且符合条件的公告图片可见，头像等其他用途图片不可见。
3. 文件名搜索、确定排序和共享分页约束正确；接口不暴露管理列表的使用位置数据。
4. 多篇公告共享同一附件、同篇重复引用、保存移除图片以及选择后附件被删除的行为符合现有引用模型。

实现阶段运行相关富文本、公告前后端和契约测试。浏览器验证重点覆盖真实文件预览、批量操作、焦点与键盘、撤销重做、明暗主题和窄屏布局；Playground 使用静态图片库适配器验证通用能力，不依赖生产附件服务。按仓库要求在沙箱外完成 `pnpm check`，并按需更新富文本公开配置说明及 README 的功能概览。
