# 图标中英文搜索质量改进与小样验证

## 目标与当前结论

最终处理范围为当前锁定图标包中的全部内置图标集，包括定义、别名和明确的分类关系。工作包含元信息提取检查、语境误译纠正、中英文等义表达补充，以及有完整表达依据的中文连续与空格写法互搜。

先用真实图标的小样验证维护方法和检索行为，再决定是否开始全量处理。小样通过只说明可以继续，不证明全库语义正确。全量阶段仍须分批复核并交付处理清单。

本文件是已批准、尚未实施的设计方案。已只读核对下文图标及维护记录；候选表达尚未写入维护数据，30 条查询尚未在修改后的真实索引中执行，不把预期结果表述为实验结果。设计审阅阶段仅更新本文件，未修改实现或重建索引。

本设计承接 [上一版图标搜索设计](./2026-09-13-icon-search-design.md)。该文档已 completed，保持冻结。本次继续使用已有数据库派生索引、后台更新和两个入口共用的检索服务。

维护数据不要求兼容旧格式，直接采用下文统一的有来源表达模型，不保留旧字段或双格式读取。已确定保留的英文名称、ID、前缀及多条件搜索属于产品行为要求，与旧数据格式兼容无关。

## 现状与证据

2026-10-02 检查时，安装的 `@iconify/json` 为 `2.2.533`；维护 manifest 的图标包版本为 `2.2.525`，数据版本为 `chinese-9`。两者版本不同本身不表示数据失效，仍按实际归属与源文校验。

- [现有文本派生](../../apps/server/src/modules/icons/search/text.ts)按空白、英文连字符与斜杠拆词。中文连续文本保持完整；英文纯字母词长度至少为 2 时可前缀匹配。普通查询各词项取 AND。
- [现有查询](../../apps/server/src/modules/icons/search/repository.ts)优先匹配完整名称或译文，其后为完整词项、英文前缀；来源与集合限制在分页前生效。
- [Lucide 维护数据](../../apps/server/resources/icon-search/translations/lucide.jsonl)中，`log-out` 既有“退出登录”，又有 `log → 日志`、`out → 外`。`folder-open` 只有“文件夹”和“打开”两个独立词。`search` 只有“搜索”。
- [MDI 维护数据](../../apps/server/resources/icon-search/translations/mdi.jsonl)中，`trash-can` 的 `can` 被译成“罐头”。
- [Open Iconic 维护数据](../../apps/server/resources/icon-search/translations/oi.jsonl)的 `account-logout` 已有“登出”，说明不同图标间的等义表达覆盖并不一致。

这些记录能证明存在数据问题，不能证明拟议匹配方式的正确性、排序质量或性能。

## 语义边界与方案选择

补充表达必须与当前归属、源文及语境中的含义一致。对象、动作、方向、否定和状态不能因补词而改变。近义词只有在当前语境中满足该条件时才收录。

检索质量以能帮助用户找到目标图标的有意义查询为准，不以保留所有旧词项或增加命中数量为目标。例如，机械拆译产生的孤立词“变体”不作为必须保留的召回目标，不为它扩展来源边界或补充表达。对象、动作、方向和状态等有实际意义的查询仍需核对；原始名称和 ID 检索继续保留。

例如，`log-out` 可以有“退出登录”“登出”以及经确认的英文写法；`bell` 不能仅因可能用于通知而增加“通知”“提醒”。不把“注销账户”视为“退出登录”，也不把垃圾桶的可能用途直接变成“删除”检索词。

| 方案 | 取舍 |
| --- | --- |
| 只修正和补齐译文 | 改动较小，但常见等义表达与完整词组的输入差异仍存在 |
| 按归属统一维护完整表达，原名检索独立派生 | 本设计采用；组成概念通过独立来源记录表达，语义判断留在维护阶段，需要小样验证表达与 AND 的衔接 |
| 查询时使用全局同义词表或自动语义拆解 | 容易跨语境传播含义、改变查询条件，本次不采用 |

原始英文名称检索与语义表达维护分别处理：

- 完整 ID、原始名称及现有名称词、英文前缀检索继续保留。本次不全面重写原始英文名称的拆词规则。
- `log` 仍可因为原名称词或前缀而找到 `log-out`、`logout`、`logs`；这不构成给退出登录图标添加“日志”译文的依据。
- 修正机械拆译，并为确认的等义表达保留完整性。新增 `sign out` 不自动生成独立的 `sign`、`out` 语义检索词。
- 同一个源词在不同归属下独立校对；不通过同义词链递推其他表达，不自动把别名的维护数据继承给父图标或其他别名。

不增加用途推断、SVG 语义识别、全局同义词传播、拼写纠错、拼音、繁简转换、通用中文分词、词干化或运行时模型调用。不新增图标管理字段、搜索选项或独立搜索服务。

## 数据组织与职责

继续从当前图标包自动读取完整清单、原始名称和明确分类关系，维护数据保存在现有 `apps/server/resources/icon-search/` 中。

### 统一的有来源表达记录

每条记录仅包含 `kind + owner + source + expressions`。前三项说明归属和依据，`expressions` 是该源文在当前语境下可以使用的一组等义表达；不再区分翻译、别称和书写变体，不设置逐项分词开关。

- `kind` 为图标或分类，`owner` 分别为图标 ID，或 prefix 与分类名的组合。
- `source` 为包内的完整名称、完整分类名，或其中按明确词边界对齐的连续词／词组。例如 `credit-card-off` 可以使用 `credit-card` 作为来源，不能从 `card` 内截取 `car`。来源验证保留原词序和重复词位置，不用去重后的词集合判断连续性。
- `expressions` 至少包含一项有效文本，可为中文或英文。每项均作为完整表达匹配，不自动拆词、生成前缀或递推其他同义词。同一数组中的不同写法互为可选匹配，不要求查询同时包含它们。
- 每个表达都须对应当前 `source` 的含义，不能把整个复合词的含义挂在一个不等义的组成词上。结构校验能证明源文存在，语义是否成立仍需校对。
- 记录按归属和规范化源文唯一、稳定排序；表达保留可读原文，按统一匹配键去重。

例如，退出登录只有一个完整含义记录：

```json
{
  "kind": "icon",
  "owner": "lucide:log-out",
  "source": "log-out",
  "expressions": ["退出登录", "登出", "log out", "logout", "sign out", "sign-out"]
}
```

“打开文件夹”包含可独立检索的组成含义，分别记录；以下各行是不同来源记录：

| 图标 | source | expressions |
| --- | --- | --- |
| `lucide:folder-open` | `folder` | `文件夹` |
| `lucide:folder-open` | `open` | `打开` |
| `lucide:folder-open` | `folder-open` | `打开文件夹` |

前两条可以共同满足“文件夹 打开”的 AND 查询，第三条支持完整表达及中文空格等价。不能把 `文件夹`、`打开` 都写入 `source: folder-open` 的表达数组，那会错误声明它们各自与整个名称等义。`sign out` 不需要拆分开关：不为其组成词额外维护不成立的含义即可。

分类中的并列概念也按各自来源记录。例如 `Account / User` 的 `Account` 与 `User` 分别维护“账户”与“用户”，仍保持分类身份；不能仅把旧的“账户 用户”字符串整体搬入一个表达而丢失独立条件。

### 原名派生、权重与格式替换

图标包原始名称词、分类原文、prefix 和集合名称仍直接派生字面检索字段，保留已确定的原名及英文前缀行为，不在维护记录中重复保存这些基础数据。中文译法、等义叫法和额外英文写法统一通过 `expressions` 进入表达索引，不再另走一套翻译拆词流程。

只有 `source` 等于完整图标名称的表达获得完整名称匹配层级；名称组成词／词组的表达在词项层级匹配，分类表达始终保持辅助身份。该身份由来源决定，与表达的语言、长度或是否被称为译文无关。

构建负责归属和结构校验、合入有效表达及确定性派生。派生文档保存原始词项与英文向量，以及主、辅完整表达和完整名称表达身份。任何维护表达均不经通用拆词函数自动变成多个检索词；一个表达可以单独满足一个查询条件，多个表达仍可分别满足多条件查询。

新维护文件按集合保存于 `apps/server/resources/icon-search/expressions/`，manifest 同步改用新格式与文件类型。经语境校对的旧译文转换为上述记录，旧 `translations` 字段与目录退出正式构建输入；不能只批量改字段名，因为并列概念和复合词需要重新核对来源与记录边界。构建仅接受新格式，不增加旧格式适配器。

同时更新运行时产物版本、检索规则版本与内容指纹，重建数据库派生索引。小样通过后再做全量格式整理与语义维护；实验使用的旧版本派生数据仅作为固定对照夹具，不构成正式应用的旧格式兼容机制。

自定义图标不接受自动翻译或等义词补充，用户输入仍是其数据来源。保留关键词现有词项行为；一个用户显式填写的完整中文关键词可参与下文的空格等价匹配，但不能把两个独立关键词自动拼成新表达。

## 查询与排序的候选行为

### 原始词项与维护表达共同匹配

完整合法 ID 仍只精确查找该 ID。其他输入先做现有 NFKC、大小写与空白归一化，同时保留识别完整表达所需的文本边界。

查询的全部条件仍取 AND，每个条件可以由原始字面词项或当前图标拥有的一条完整表达满足。完整表达可以覆盖查询中的连续片段，其余查询内容仍必须匹配；多个独立含义记录也能各自满足一个条件。保留所有合法的完整覆盖方式，不能删除无法匹配的词后重试。

完整表达匹配须验证当前图标确实拥有该表达。不能先通过全库词典选定一个全局分法，再用它替代所有图标原有的 AND 条件。一个词组的新增不能使其他图标原有的独立词命中消失。

- `lucide sign out` 可以是 `lucide` 与完整表达 `sign out` 两个条件。
- `sign out qzxmissing` 不能忽略最后一个条件。
- 新增英文表达本身使用完整匹配，不自动启用词内前缀、调换词序或拆词。仅因维护了 `sign out`，不能让 `sig ou`、`out sign` 或 `sign` 命中该表达。原始名称路径产生的匹配仍按原规则处理。
- 英文有无空格、连字符或连写的互通需要明确的完整写法记录，例如 `log out`、`log-out`、`logout`。不全局删除英文空格或分隔符来猜测等价关系。

### 中文空格等价

对于内容仅由汉字及其间空白组成的已维护完整表达，使用去除其中空白后的完整键比较。该键只用于完整表达，不替代所有查询的词项归一化；数字、中英紧连内容和标点不套用此规则。

因此，有完整表达“打开文件夹”时，“打开文件夹”“打开 文件夹”可以通过同一表达命中；只有“打开”“文件夹”两个独立含义记录时，仍只有带空格输入能通过两个条件的 AND 路径命中。两个输入的全部候选集合不要求相同，但同一完整表达的匹配等级不因空格变化而降低。

未知连续中文不自动分词，不在一个查询词内部做任意子串搜索。“可见”不能通过“不可见”这一完整表达命中。完整中文表达可以和其他条件组合，例如 `lucide 打开 文件夹`。

### 排序、去重与分页

继续使用三个层级：完整名称或其完整等义表达命中；全部词项或表达完整命中；需要原英文词项前缀才能满足的命中。

每条完整覆盖查询的路径使用同一排序元组：匹配层级升序、中文主要字段命中数量降序、英文相关度降序、现有图标集与单色偏好降序、完整 ID 字节序升序。

- 整条查询匹配完整名称或归属完整名称的表达时为第一层；其他全部条件完整命中为第二层；至少一个原英文词项依赖前缀才满足时为第三层。
- 中文主要字段命中数量按该路径的去重条件计数。含汉字的独立查询词在主要词项中命中计 1；含汉字的完整表达在主要表达中命中计 1，不按内部字符或空格段数累加。分类表达计 0。完整 ID 路径沿用现有唯一结果行为。
- 英文相关度仅对该路径中未被完整表达覆盖的原英文查询词计算，使用现有 `simple`、`ts_rank` 权重及 normalization = 0；没有这些词时为 0。英文表达本身不拆词或增加相关度分数。
- 同一图标只返回一次，取所有合法路径中按上述元组排序最优的一条，不把多条同义表达或重复路径的分数累加。条件去重不允许漏掉未覆盖的输入。

完整表达与独立词路径可以得到不同分数，但其比较方式固定。分类不会因增加表达升级成主要字段，英文原名精确命中仍可凭既有英文相关度排在同层级的英文别称命中前。

先对全部合法候选确定最佳路径和排序，再分页，不在单一路径提前截取后丢弃其他路径的更好结果。游标记录实际使用的排序元组，继续绑定规则、查询和索引版本。

这些是小样必须验证的行为要求，不预先宣称词组查询的 SQL 组织和性能已经可行。后续实现先用现有数据库能力完成实验；若完整输入覆盖、排序、分页或性能不能同时满足，停止全量处理，回到设计阶段调整，不能静默放宽条件。

| 22 | `打开文件夹` | G | H；不能从两个零散词拼出表达 |
| 23 | `打开 文件夹` | G、H | G 排在 H 前；H 的旧 AND 召回不能丢失 |
| 24 | `文件夹 打开` | G、H | 两个独立词仍可通过原 AND 路径匹配 |
| 25 | `lucide 打开 文件夹` | G | H；完整表达与其余条件组合 |
| 26 | `打开 文件夹 qzxmissing` | 无 | G、H；两条路径均不能忽略未知条件 |
| 27 | `铃铛` | I | 原有正确译文仍可检索 |
| 28 | `通知` | 无 | I；不按可能用途扩词 |
| 29 | `lucide:trash-2` | L | 只返回 L，不替换为 E |
| 30 | `ＳＩＧＮ　ＯＵＴ` | A、B、C | 大小写、全半角和空白归一化适用于表达 |

“无”表示本行没有要求命中的目标，不表示全库查询必须返回空列表。例如“罐头”可以命中图库中真正表示罐头的其他图标。

## 实验步骤与进入全量的条件

### 第一阶段：固定小样并运行真实检索

设计审阅确认候选数据和预期后，实施阶段先记录当前实现的基线，再使用候选数据与匹配逻辑运行同一批查询。先在上述 12 个图标的受控数据集中验证完整结果与排序；随后将仅这批数据的改动合入当前全量基础索引进行实验，检查其他图标的竞争结果与性能。

两次均使用真实维护数据、构建产物和数据库检索链路，不用字符串模拟器代替实际查询。记录图标包版本、维护数据与规则版本、查询、两个入口返回的 ID 和顺序、基线与候选的差异。

必须满足：

1. 受控索引的 30 条已固定预期全部通过，包括负例、完整输入覆盖和 H 的旧 AND 对照。全量索引另通过图标库分页检查表中指定目标的命中、不命中及相对顺序，避免返回上限掩盖目标；不要求所有指定目标均进入全量结果前 20 项。
2. 对全量索引下这 30 条查询另外保存前 20 项，由独立复核者核对新增结果的元信息与表达依据。该项检查前排结果质量，与上一项的候选成员检查分别报告。发现新增误关联先修正并重跑；不能用正确召回的增加抵消已知错误。
3. 现有完整 ID、英文前缀、多词 AND、否定完整词、主辅字段、两个入口一致性、来源筛选、别名身份和自定义关键词行为无未约定的回归。
4. 明确验证多路径去重、完整表达优先，以及数据不变时多页无重复遗漏。现有“可见”不命中仅有“不可见”的夹具继续通过，并增加完整表达的相同边界用例。来源校验覆盖名称中的连续复合词、重复词位置和禁止词内截断；并列分类概念转换后仍可独立组合查询。

### 第二阶段：独立复核

首批规则固定后，由未负责首批调规则的复核者从首批之外选择至少 6 个图标，来自至少 3 个其他图标集，覆盖专业多义词、品牌与普通词重名、否定或状态、分类辅助字段、别名归属。每个图标至少固定 2 条正例和 2 条负例，再运行候选方案。

复核直接检查原始元信息和候选表达，不以生成者的解释作为正确性证据。名称和元信息不能消除歧义的项保留原文，不要求猜出译法。该处理决定也记录在复核结果中。

全部预期通过且无已知新增误关联后，才允许进入全量维护。若用复核失败案例调整了规则，这组案例转为开发样本；重新选取独立复核样本，不能继续称原样本为独立验证。

### 性能与可行性

沿用上一版基线：Apple M4、10 个逻辑 CPU、24 GiB 内存、macOS arm64 的 PGlite 环境，记录实际 Node.js、PGlite 版本与数据版本。当前全量索引上默认返回 60 项，预热核心查询每类 P95 不超过 50 ms，每批 10 请求突发 P95 不超过 200 ms。

测量原英文词项、完整中文词、新增英文表达、带空格中文表达、中英混合、多词宽匹配和分页；同时运行最大合法长度、多短词查询，确保表达识别不会绕过原查询上限或出现不可控的路径膨胀。报告原实现与候选的分类数据，不以混合平均值代替慢查询表现。

小样索引的耗时不能代表全库成本。全量维护完成后必须用最终完整数据重测，记录索引体积、构建及导入耗时、内存和业务混合负载。生产 PostgreSQL 有目标环境时单独复测；没有时明确记录该限制，不用 PGlite 结果代替生产结论。

## 全量维护与交付

通过实验后，处理当前锁定图标包的全部图标集。先检查名称、别名和明确分类关系是否充分提取，再逐归属检查已有译文、补充完整表达和同语境等义表达。

以当前清单生成全量处理账目，覆盖全部定义、别名和分类归属，记录修正、新增、确认保留，以及证据不足而保留原文的内容。不能只扫描缺中文的条目，也不能将“已有中文”计为语义复核完成。处理中途升级图标包时，先固定新的输入版本并核对清单差异。

生成与复核分开进行。可以按经确认的语境批量处理重复模式，但每个落点均验证归属与源文；复合词、多义词、专业术语、品牌、否定和方向不能只凭通用词表替换。维护使用的工具或模型不构成正确性依据，本设计不绑定具体产品。

每批执行结构校验并复核处理结果。批次结束时，由未负责本批生成和初次判断的复核者，对每个图标集在本批出现的“纠错”“新增等义表达”“新增完整词组”“确认保留”“移出有效数据”五类处理结果分别抽查至少 5 条，不足 5 条时全部检查；抽样须覆盖该类结果实际出现的各类高风险内容，必要时增加数量。“确认保留”检查旧表达的来源及语境是否成立，“移出有效数据”检查移出依据，避免误保留错误译文或误删正确表达。风险覆盖指抽样包含各风险类别，不表示抽查了所有高风险记录。发现错误时停止合入该批，复核同一生成或判断规则影响的全部记录，修正后重新检查。该抽查用于检查处理方法，不代替全量处理账目。

缺少可靠中文或等义表达的记录保留原文检索，单列原因，不计入已确认语义覆盖。已确认错误的内容删除；经过具体语境复核仍无法确认的已有内容移出有效维护结果并记录，不因其曾经存在就继续当作已确认数据使用，也不能仅因通用词表未收录就判为无法确认。全量完成指全部归属已按此流程处理并有去向，不承诺所有名称都能翻译或任何自然说法都能命中。

确认后的维护数据、格式和必要回归用例纳入仓库；一次性处理账目、未确认项明细、搜索对照及性能报告沿用项目外临时报告的约定，并在交付时给出可访问路径。更新维护 README 与项目搜索说明。本设计的所有样稿直接保存在本文件，无额外资源依赖。
